# Introduction to Jekyll

**Jekyll** is one of the most influential and widely used **static site generators (SSGs)**.  
Originally created by Tom Preston-Werner, the co-founder of GitHub, Jekyll powers **GitHub Pages**, the free hosting service that allows users to publish websites directly from their Git repositories.

Jekyll is written in **Ruby** and designed to transform plain text—typically Markdown files—into a complete static website.  
Its philosophy is simple: **"No database, no CMS, just files."**

---

## 1. What Is Jekyll?

Jekyll converts structured text content (like Markdown or HTML) combined with templates (written in Liquid, a Ruby-based templating language) into a ready-to-deploy static site composed of plain HTML, CSS, and JavaScript.

It follows a straightforward workflow:

1. You write your content in Markdown.  
2. You define templates and layouts in HTML with placeholders.  
3. You run the `jekyll build` command to generate static pages.  
4. You deploy the `_site` folder to your web host or GitHub Pages.

In essence, **Jekyll acts as a content compiler** — turning your text files into a full website.

---

## 2. Key Features

| Feature | Description |
|----------|-------------|
| **Markdown Support** | Write content using simple Markdown syntax. |
| **Liquid Templating** | Use variables, loops, and conditionals to build flexible layouts. |
| **Front Matter** | Add metadata (title, date, layout) to the top of each page or post. |
| **Collections & Data Files** | Organize custom types of content beyond posts and pages. |
| **Permalinks & URLs** | Configure how URLs are generated for posts and pages. |
| **Plugins & Themes** | Extend functionality or customize appearance easily. |
| **GitHub Pages Integration** | Deploy automatically via GitHub’s built-in Jekyll support. |

## 3. Directory Structure

A typical Jekyll project looks like this:

```

my-site/  
├── _config.yml # Main configuration file  
├── _posts/ # Blog posts (Markdown files)  
│ ├── 2025-11-10-hello-world.md  
├── _layouts/ # Layout templates  
│ ├── default.html  
│ ├── post.html  
├── _includes/ # Reusable HTML snippets  
├── _data/ # YAML or JSON data files  
├── _site/ # Generated static site (output folder)  
├── assets/ # Images, CSS, JS  
└── index.md # Home page content

````

Each part serves a specific purpose:
- `_layouts/` defines the overall HTML structure.  
- `_includes/` contains reusable components like headers or footers.  
- `_posts/` stores blog articles named by date convention.  
- `_site/` is generated by Jekyll and should not be manually edited.

---

## 4. Front Matter

Every Jekyll page or post starts with a **YAML front matter block**, which stores metadata.

Example:

```markdown
---
layout: post
title: "Hello Jekyll"
date: 2025-11-10
author: Matt Li
tags: [jekyll, web, cs101]
---

This is my first post using **Jekyll**!
````

The variables defined here can be accessed in templates, making Jekyll highly customizable.

---

## 5. Liquid Templating

Jekyll uses **Liquid**, a template language created by Shopify, to render dynamic content during site generation.

Example:

```html
<h1>{{ page.title }}</h1>
<p>Published on {{ page.date | date: "%B %d, %Y" }}</p>

{% for post in site.posts %}
  <li><a href="{{ post.url }}">{{ post.title }}</a></li>
{% endfor %}
```

Liquid provides:

- `{{ variable }}` for output
    
- `{% tag %}` for logic (loops, conditionals)
    
- Filters (like `date`, `upcase`, `truncate`) for formatting

## 6. Configuration (`_config.yml`)

The `_config.yml` file defines site-wide settings.

Example:

```yaml
title: My CS101 Notes
description: A personal documentation site built with Jekyll
baseurl: "" # the subpath, e.g. /blog
url: "https://mattli.github.io"

theme: minima
markdown: kramdown

plugins:
  - jekyll-feed
  - jekyll-seo-tag
```

You can control output directories, Markdown processors, plugins, and URL structures all from this file.

## 7. Writing Posts and Pages

### Blog Posts

Save posts in `_posts/` with filenames like `YYYY-MM-DD-title.md`.

Example:

```markdown
---
layout: post
title: "Introduction to Static Site Generators"
date: 2025-11-10
---

Static site generators are tools that build websites from plain text.
```

Jekyll automatically lists them by date under `site.posts`.

### Pages

Pages (like `about.md` or `contact.md`) can live in the root directory or subfolders.  
They also use front matter but are not listed as posts.

---

## 8. Themes and Plugins

### Themes

Jekyll supports themes that define styles and layouts.  
Install a theme from RubyGems:

```bash
gem install jekyll-theme-cayman
```

Then, in `_config.yml`:

```yaml
theme: jekyll-theme-cayman
```

### Plugins

Plugins extend Jekyll’s functionality — from generating sitemaps to adding search support.

Example:

```bash
gem install jekyll-seo-tag
```

and in `_config.yml`:

```yaml
plugins:
  - jekyll-seo-tag
```

## 9. Building and Serving the Site

To create and view your Jekyll site locally:

```bash
gem install bundler jekyll
jekyll new my-site
cd my-site
bundle exec jekyll serve
```

Then visit:

```
http://localhost:4000
```

Jekyll will automatically rebuild your site each time you save a file.

To generate the static files manually:

```bash
bundle exec jekyll build
```

The output appears in the `_site/` directory.

---

## 10. Deploying to GitHub Pages

One of Jekyll’s greatest strengths is **native GitHub Pages integration**.  
Simply push your site repository to GitHub, and GitHub automatically builds and serves your site.

Steps:

1. Create a new repository named `<username>.github.io`
    
2. Push your Jekyll site to the repository
    
3. Enable GitHub Pages in repository settings (if needed)
    

Your website will be live at:

```
https://<username>.github.io
```

For project pages, push to the `gh-pages` branch or use GitHub Actions for CI/CD automation.

## 11. Advantages and Limitations

### ✅ Advantages

- Fully static, fast, and secure
    
- Easy to host (especially on GitHub Pages)
    
- Simple text-based workflow (Markdown + Git)
    
- Flexible templating system
    
- Strong plugin and theme ecosystem
    

### ⚠️ Limitations

- Requires Ruby environment (setup can be tricky for beginners)
    
- No built-in dynamic features (e.g., comments need third-party services)
    
- Rebuilding the entire site for every change can be slow on very large projects
    

---

## 12. Example: Building a Personal Blog

To build a blog quickly:

```bash
jekyll new myblog
cd myblog
bundle exec jekyll serve
```

Then edit `_config.yml` and add posts under `_posts/`.  
You can customize the layout in `_layouts/` and publish it directly to GitHub Pages.

---

## 13. Jekyll in the Modern Web

Although newer tools like **Hugo**, **Next.js**, and **Eleventy** have emerged, Jekyll remains foundational in static site development.  
Its simplicity, transparency, and deep GitHub integration make it an ideal choice for educational projects, personal blogs, and documentation sites—such as **CS101-ICS**.

---

## 14. Conclusion

Jekyll embodies the philosophy of minimalism and automation in web publishing.  
By separating content, layout, and configuration, it provides developers with a clean, reproducible way to build static websites that are fast, reliable, and easy to maintain.

For students and developers, learning Jekyll is an excellent introduction to static site generation, Git-based workflows, and the broader concepts behind the **Jamstack** architecture.
